# Security policy

## Current status

Hummingbird Forge is an unimplemented, design-stage project. No production platform or official capability pack is currently released. There are no supported production versions and no production-security guarantees. Architectural controls described in this repository are requirements or proposals, not evidence of enforcement.

## Report concerns privately

Do not post security concerns, sensitive vulnerability details, exploit steps, credentials, personal data, or production logs in public issues, discussions, pull requests, or AI prompts.

If GitHub private vulnerability reporting is enabled for this repository, use **Report a vulnerability** in its [Security area](https://github.com/nissifield/ftlbird-waypoint/security). Availability has not been confirmed; do not assume a report is private without checking the submission screen.

If that option is unavailable and no private contact is published, open an issue titled **Request for a private security reporting channel** with only: “Please provide a private channel for a security report.” Include no affected systems, technical description, attachments, or exploit details. Wait for a human maintainer to provide a private route before sharing the concern. If no route is established, keep the details private.

No security contact address or response-time commitment is established here. Maintainers should confirm the private reporting route and handling capacity before asking for sensitive evidence.

## Public architecture review

Generic, hypothetical threat-model questions are welcome through the security review template. They must contain no sensitive finding or details of a real vulnerable system. When in doubt, request the private channel above.

Maintainers should establish affected scope, handling access, remediation review, and coordinated disclosure with the reporter before any publication. This policy does not authorise testing systems, accessing data, or disclosing an upstream project's vulnerabilities publicly.
